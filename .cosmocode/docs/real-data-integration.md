# 真实数据接入空压站调度程序 —— 集成说明与缺口分析

## 1. 结论摘要

- 已将提供的 9 个真实数据文件接入程序，程序由「5 台虚构机组 + 干燥机 + 储气罐」的演示站点，重构为「2 台真实机组（4#、5#）」的真实站点。
- 运行管理、能效与收益、数据与策略、设备健康、智能调度、Agent 助手等页面的数据来源已切换为真实数据聚合结果。
- 「逐字段完美替换」在这份数据上无法达成。原因分三类：程序自身的设计缺陷、程序缺少的必要功能、真实数据自身的质量问题。下文逐条列出。

## 2. 数据资产与预处理

### 2.1 输入（9 个文件）

| 文件 | 规模 | 关键内容 |
| --- | --- | --- |
| 设备运行参数.csv | 26.5 万行 × 23 列 | 4#/5# 排气压力、实时流量、ABC 相电流、功率、IGV、BOV、油压、油滤压差、空滤压降 |
| 设备状态监测.csv | 26.5 万行 × 39 列 | 三级振动、轴承/绕组/油温、排气温度、冷却水/中冷/后冷温度 |
| 用气负荷数据.csv | 26.5 万行 × 6 列 | 总流量、负荷率、负荷等级、波动率(15min/日级) |
| 环境参数.xlsx | 26.5 万行 × 4 列 | 站房温度、湿度、大气压 |
| 管网运行数据.xlsx | 26.5 万行 × 6 列 | 母管压力、支路流量、压差 |
| 维护保养记录.xlsx | 26.5 万行 × 7 列 | 总运行/负载时间、下次保养剩余时间 |
| 运行事件记录.xlsx | 26.5 万行 × 9 列 | 状态、加卸载、预警、故障 |
| 设备档案.json | 2 台机组 | 阿特拉斯 ZH1250-6 参数与保养计划 |
| 指标释义.json | — | 指标中文释义、阈值与计算口径 |

时间范围统一为 **2026-03-12 00:00:00 ~ 2026-09-12 00:00:00**，分钟级，共 264,961 行。

### 2.2 预处理产物

- 脚本：`scripts/build_real_dataset.py`（pandas + openpyxl）
- 产物：`src/data/generated/realDataset.json`（约 183 KB），包含
  `meta / devices / daily / hourly / realtime / forecast / metrics / quality / events / maint`
- 类型封装：`src/data/realDataset.ts`

预处理做了四件事：

1. **xlsx 修复**：4 个 xlsx 内部条目使用 Windows 反斜杠路径（`xl\workbook.xml`），标准解析器直接报错，脚本按正斜杠重新打包后读取。
2. **单位归一**：压力由 MPa 换算为 bar（×10），与程序既有 `pressureBar` 字段对齐。
3. **降采样聚合**：分钟级 26.5 万行聚合为日级 185 条、小时级（近 30 天）721 条、实时（末尾 6h）361 条、预测 16 点，避免把 200 MB 直接塞进浏览器。
4. **质量标注**：抽取真实数据中的字段缺陷并生成质量清单。

## 3. 实体与口径映射

| 程序原模型 | 真实站点 | 处理方式 |
| --- | --- | --- |
| AC-01 ~ AC-05（3 离心 + 2 螺杆） | 4#、5# 两台离心机 | 映射为 `AC-04`、`AC-05` |
| DR-01/DR-02 干燥机 | 无 | 移除 |
| AT-01/AT-02 储气罐 | 无 | 移除 |
| 压力 0.78~0.84 "bar" | 母管压力 0.48~0.71 MPa | 换算为 4.8~7.1 bar，合格带取 5.0~6.4 bar |
| 额定总流量 700 m³/min | 537.8 m³/min | 采用真实值 |
| 30 天小时级、以"当前"为实时 | 6 个月分钟级历史归档 | 全部改为真实范围；实时段取数据末尾 6h |
| 人工基线期 / AI 调度期 | 无 AI 干预，单一连续归档 | 以数据中点为界，前/后半程对比 |

## 4. 无法完美集成的问题清单

### 4.1 程序缺陷（设计层面）

1. **压力单位口径混乱**：字段名为 `pressureBar`、阈值写作 0.78~0.84，真实数据却是 MPa（0.58~0.66）。程序把 MPa 数值当 bar 使用，相差 10 倍，属于单位口径缺陷。已统一换算并按真实分布设定阈值。
2. **设备数量强耦合**：机组编号 `AC-01`…`AC-05` 硬编码在 `types`、`scheduler`、`appStore`、`metrics`、`agent` 与 8 个页面中。减少或增加机组需要修改十余处，耦合过重。
3. **把历史归档当实时**：`DEMO_NOW` 取应用加载时刻，`refreshRealtime` 用随机抖动伪造实时刷新。面对一份已结束的历史数据，这套实时语义无法成立。
4. **产能与负荷率口径不一致**：程序按 5 台合计 700 m³/min 计负荷率，真实额定总流量为 537.8 m³/min。
5. **演示叙事与虚构设备写死**：告警、诊断、工单、方案、待办几乎全部绑定虚构机组（如"AC-03 低载""AC-01 喘振"），换数据后这些叙事立即失效。

### 4.2 程序缺失功能（能力层面）

1. **没有数据接入层**：源码中零 `fetch`、零文件解析，所有数据是 `initial.ts` / `timeseries.ts` 内写死的 TS 常量。要消费外部数据，必须新增解析、聚合、异步引导能力。
2. **没有数据质量校验与单位归一**：无法识别恒零、全空、溢出、负值等真实数据缺陷，也没有统一的单位换算层。
3. **没有区分"历史归档 / 实时流"的时间轴能力**：无法在固定历史数据上做回放或时间旅行。
4. **没有 AI-vs-基线对照的实验设计**：程序的收益 KPI 默认存在"人工基线期 / AI 调度期"两段，真实数据为连续运行归档，缺少 AI 干预前后对照。任何"节能收益"都无法从这份数据中真实推导。
5. **健康评分与喘振风险没有真实算法**：`healthScore`、`surgeRisk` 原为手写常量，程序没有从振动/温度/IGV/BOV 计算它们的模型。
6. **没有大数据量处理与多设备扩展能力**：200 MB 原始数据无法直接进入浏览器；新增机组需要改代码。

### 4.3 真实数据自身的问题（与程序无关）

1. **机组数量不足**：仅 2 台机组，无干燥机、储气罐，程序的"多机协同 + 辅机"场景缺少数据支撑。
2. **B 相电流全程恒为 0**（4#、5# 均如此），三相电流监测不完整，A 相另有 1944 A 级尖峰。
3. **加卸载字段全程为空、预警字段全程为 0**，无法还原加减载与预警时序。
4. **4# 下次保养剩余时间出现 4.29e9 级异常值**，疑似单位或溢出错误。
5. **4# 总运行时间出现 65535（2^16−1）上限值**，疑似 uint16 溢出。
6. **空气过滤器压降过半为负值**，量程或取压方向存疑。
7. **负荷率最高 111%**，与额定总流量 537.8 m³/min 的口径不一致。
8. **无派生业务字段**：没有健康分、喘振裕度、AI 干预前后、排产、工单、策略等业务数据。

## 5. 已做的取舍与降级处理

| 项 | 处理方式 | 说明 |
| --- | --- | --- |
| 健康评分 | 以振动、绕组温度、排气温度的经验罚分推导 | 未定义，属程序侧补算 |
| 喘振风险 | 依据 BOV 闭度阈值判断 | 真实数据无喘振标注 |
| 压力合格带 | 取真实母管压力 5%~99% 分位 5.0~6.4 bar | 只给了"压差下限 0" |
| 基线 / 近期 | 以数据中点（2026-06-12）分界 | 替代原"人工/AI"两期，KPI 语义已改为真实对比 |
| 保养剩余时间 | 大于 1e5 的异常值置空 | 避免 4.29e9 污染展示 |
| 运行时间 | 大于 5e4 的异常值置空 | 规避 65535 溢出 |
| 负荷预测 | 用数据末尾一日分时形态外推 | 真实数据无未来段 |

## 6. 复现方式

```bash
# 1. 安装依赖
npm install

# 2. 由真实数据重新生成聚合数据集
pip3 install --break-system-packages pandas openpyxl
python3 scripts/build_real_dataset.py

# 3. 类型检查与生产构建
npx tsc --noEmit
npm run build

# 4. 生产预览
npm run preview
```

## 7. 本轮已完善的缺陷与功能

针对第 4 节列出的问题，已完成以下改造：

| 原问题 | 类别 | 完成情况 |
| --- | --- | --- |
| 压力单位口径混乱 | 缺陷 | 已在预处理层统一换算为 bar，新增 `PRESSURE_UNIT` 常量说明口径；全站阈值改取真实分位 |
| 设备数量强耦合 | 缺陷 | 新增 `src/data/stationConfig.ts` 作为设备清单与阈值的单一来源；调度器、store、页面的 `AC-0x` 硬编码已移除，改为按状态/配置判定 |
| 把历史归档当实时 | 缺陷 | 新增站点时间轴 `src/data/stationTime.ts`；运行管理页支持选择数据时刻与「历史回放」（1.5s 前进 1 小时），遥测随数据时刻同步；删除随机抖动伪实时 |
| 产能与负荷率口径不一致 | 缺陷 | 站点额定总流量 537.8 m³/min、单机 268.9 m³/min 统一取自配置，负荷率按真实口径计算 |
| 数据接入层缺失 | 功能 | 新增 `scripts/build_real_dataset.py` 预处理管线；数据集外置到 `public/data/realDataset.json`，由 `main.tsx` 启动时 fetch 注入，替换数据包无需重新构建 |
| 数据质量校验 | 功能 | 预处理脚本识别 7 项缺陷（恒零/全空/溢出/负值/越界）；`useDataQualityBlock` 汇总严重项，UI 可逐项标记解决 |
| 未区分历史与实时 | 功能 | 时间轴区分「最新时段」与「历史回放中」，运行趋势、设备遥测均按数据时刻取值 |
| 健康评分无真实算法 | 功能 | 新增 `src/utils/health.ts`：由振动/绕组/轴承/排气温度/油压/BOV 闭度计算健康分、喘振风险与可解释依据，替代写死常量 |
| 大数据量处理 | 功能 | 分钟级 26.5 万行聚合为日/小时/实时序列，主包 420 KB，数据文件按需加载 |

烟测：`esbuild` 打包脚本验证时间轴采样、窗口长度、边界钳制、健康算法与配置一致性均通过。

### 真实数据驱动页面功能（不单列数据）

数据通过现有页面功能呈现，不额外罗列：

- 运行管理：机组状态、母管压力/流量/功率/加载率趋势取自真实时序，支持时间轴与历史回放
- 设备健康：健康评分与风险由真实测点算法计算；振动/轴承温度趋势取真实序列最近 48 小时
- 能效与收益：逐日能效、比功率、压力合格率、低载时长、压力波动均取自真实数据；KPI 表区分「真实数据」与「赛题目标」
- 数据与策略：数据源列表由 7 个真实文件推导（协议=文件类型、点位数=字段数、质量=测点覆盖率），数据质量问题来自真实数据校验
- 智能调度 / Agent：以真实设备档案、真实负荷预测与真实健康状态为输入
- 87 个测点全部参与上述页面的统计与展示；设备运行参数、状态监测、管网、环境、负荷、保养、事件分别进入对应功能

## 8. 后续建议

1. **补齐数据接入层**：把 `build_real_dataset.py` 的职责产品化，支持上传新数据包后自动重建。
2. **增加数据质量门禁**：恒零、全空、溢出、越界检测应作为数据源接入的前置校验，并驱动"禁止生成方案"。
3. **解耦设备模型**：以配置驱动机组列表，移除页面与算法中的 `AC-0x` 硬编码。
4. **区分历史与实时**：为站点引入明确的数据时间轴，历史回放与实时监看分离。
5. **重定义收益口径**：在无 AI 干预的数据上，把 KPI 明确标注为"真实两期对比"，避免与"AI 节能收益"混淆。
6. **反馈数据缺陷**：B 相电流、加卸载、预警、保养剩余时间、运行时间、空滤压降、负荷率口径共 7 项，建议在下一版数据包中修复。
